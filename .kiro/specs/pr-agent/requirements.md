# Pull Request Agent - Requirements

## Overview

A standalone agent that creates GitHub pull requests to the HashiCorp terraform-provider-awscc repository with validated AWSCC Terraform examples. The agent operates independently from the main TANGO pipeline, processing successfully validated resources stored in DynamoDB and S3.

## User Stories

### US-1: Query Single Validated Resource (Atomic Operation)
**As a** pipeline operator  
**I want to** query DynamoDB for exactly one successfully validated resource  
**So that** I can process PRs atomically, one at a time

**Acceptance Criteria:**
- 1.1: Agent queries DynamoDB table for entries with `source='tango_pipeline'` AND `status='success'`
- 1.2: Agent filters out resources that already have PRs (`pr_status` field exists)
- 1.3: Agent returns exactly ONE resource (the oldest eligible entry)
- 1.4: Agent validates S3 files exist before proceeding
- 1.5: Agent ignores entries without `source='tango_pipeline'` (pre-existing examples)
- 1.6: Agent returns "NONE" if no eligible resources found

### US-2: Fetch Validated Content
**As a** PR agent  
**I want to** retrieve validated Terraform code and templates from S3  
**So that** I can include them in the pull request

**Acceptance Criteria:**
- 2.1: Agent fetches Terraform code from `examples/resources/{resource_name}/{service_name}.tf`
- 2.2: Agent fetches template from `templates/resources/{resource_name}.md.tmpl`
- 2.3: Agent fetches analysis report from `analysis/resource/{resource_name}/{date}.txt`
- 2.4: Agent validates file content is not empty
- 2.5: Agent handles S3 access errors gracefully

### US-3: Fork Management
**As a** PR agent  
**I want to** work with a specified fork of the terraform-provider-awscc repository  
**So that** I can create pull requests from my fork to the upstream repository

**Acceptance Criteria:**
- 3.1: Agent accepts fork repository URL as configuration parameter
- 3.2: Agent validates fork exists and is accessible
- 3.3: Agent ensures fork is up-to-date with upstream main branch
- 3.4: Agent handles authentication via GitHub token
- 3.5: Agent reports fork status before proceeding

### US-4: Repository Cloning and Branch Creation
**As a** PR agent  
**I want to** clone the fork and create a feature branch  
**So that** I can make changes without affecting the main branch

**Acceptance Criteria:**
- 4.1: Agent clones fork to temporary working directory
- 4.2: Agent creates branch with naming convention: `d-{resource_name}`
- 4.3: Agent configures git user name and email from environment
- 4.4: Agent handles existing branch conflicts (delete and recreate)
- 4.5: Agent cleans up working directory on completion or failure

### US-5: File Placement and Structure
**As a** PR agent  
**I want to** place files in the correct HashiCorp repository structure  
**So that** the PR follows project conventions

**Acceptance Criteria:**
- 5.1: Agent creates directory structure: `examples/resources/{resource_name}/`
- 5.2: Agent places Terraform code in correct location
- 5.3: Agent creates/updates template in `templates/resources/{resource_name}.md.tmpl`
- 5.4: Agent processes template content from S3 (already generated by storage agent)
- 5.5: Agent validates file paths match HashiCorp conventions

### US-6: HashiCorp Make Commands
**As a** PR agent  
**I want to** run required `make` commands for validation  
**So that** the PR passes HashiCorp's CI checks

**Acceptance Criteria:**
- 6.1: Agent runs `make tools` to install required tools (tfplugindocs, goimports, etc.)
- 6.2: Agent runs `make docs` to auto-generate documentation from templates
- 6.3: Agent sets `GOPROXY=direct` environment variable for Go operations
- 6.4: Agent captures command output for debugging
- 6.5: Agent fails fast if make commands fail
- 6.6: Agent verifies `docs/resources/{resource_name}.md` was generated by `make docs`

### US-7: Git Commit and Push
**As a** PR agent  
**I want to** commit changes and push to fork  
**So that** I can create a pull request

**Acceptance Criteria:**
- 7.1: Agent stages all modified files
- 7.2: Agent creates commit with descriptive message following conventions
- 7.3: Agent pushes branch to fork remote
- 7.4: Agent handles push failures (authentication, conflicts)
- 7.5: Agent verifies push succeeded before creating PR

### US-8: Pull Request Creation
**As a** PR agent  
**I want to** create a pull request via GitHub API  
**So that** the validated example can be reviewed and merged

**Acceptance Criteria:**
- 8.1: Agent creates PR from fork branch to upstream main
- 8.2: Agent generates PR title: `Add example for {resource_name}`
- 8.3: Agent generates PR description with validation summary
- 8.4: Agent includes link to S3 analysis report in description
- 8.5: Agent adds appropriate labels (if permissions allow)
- 8.6: Agent returns PR URL on success

### US-9: DynamoDB Status Tracking
**As a** PR agent  
**I want to** update DynamoDB with PR status  
**So that** we can track which resources have PRs

**Acceptance Criteria:**
- 9.1: Agent updates DynamoDB entry with `pr_status='created'`
- 9.2: Agent stores `github_pr_url` in DynamoDB
- 9.3: Agent stores `pr_created_at` timestamp
- 9.4: Agent handles DynamoDB update failures
- 9.5: Agent preserves existing fields when updating

### US-10: Error Handling and Cleanup
**As a** PR agent  
**I want to** handle errors gracefully and clean up resources  
**So that** failures don't leave the system in a bad state

**Acceptance Criteria:**
- 10.1: Agent cleans up cloned repository on success
- 10.2: Agent cleans up cloned repository on failure
- 10.3: Agent logs detailed error messages
- 10.4: Agent updates DynamoDB with `pr_status='failed'` on error
- 10.5: Agent provides actionable error messages to user

### US-11: Standalone Execution (Atomic)
**As a** pipeline operator  
**I want to** run the PR agent independently for one resource at a time  
**So that** I can control PR creation atomically

**Acceptance Criteria:**
- 11.1: Agent runs via command: `python create_pr.py` (processes next eligible resource)
- 11.2: Agent supports specific resource: `python create_pr.py {resource_name}`
- 11.3: Agent supports dry-run mode: `python create_pr.py --dry-run`
- 11.4: Agent validates configuration before starting
- 11.5: Agent provides progress feedback during execution
- 11.6: Agent processes exactly ONE resource per execution

### US-12: Configuration Management
**As a** PR agent  
**I want to** load configuration from environment and config file  
**So that** I can adapt to different environments

**Acceptance Criteria:**
- 12.1: Agent reads `GITHUB_TOKEN` from environment
- 12.2: Agent reads `GITHUB_FORK_URL` from config
- 12.3: Agent reads `GIT_USER_NAME` and `GIT_USER_EMAIL` from environment
- 12.4: Agent validates all required configuration is present
- 12.5: Agent provides helpful error messages for missing config

## Non-Functional Requirements

### Performance
- PR creation should complete within 5 minutes per resource
- Agent processes exactly one resource per execution (atomic operation)

### Security
- GitHub token must never be logged or exposed
- Token should have minimal required permissions (repo scope)
- Cloned repositories should be in secure temporary directories

### Reliability
- Agent must clean up resources even on failure (try/finally)
- Agent must be idempotent (can retry safely)
- Agent must handle GitHub API rate limiting
- Agent processes one resource at a time for simplicity and reliability

### Maintainability
- Agent follows existing Strands Agent pattern
- Agent uses consistent logging format with other agents
- Agent code is well-documented with clear comments

## Dependencies

- **boto3**: DynamoDB and S3 access
- **requests** or **PyGithub**: GitHub API interaction
- **GitPython**: Git operations
- **subprocess**: Running make commands
- **tempfile**: Temporary directory management
- **python-dotenv**: Load environment variables from .env file

## Configuration

New configuration parameters in `config.py`:

```python
# Load .env file if it exists
from dotenv import load_dotenv
load_dotenv()  # Load from .env file in root directory

# GitHub Configuration
GITHUB_TOKEN = os.getenv('GITHUB_TOKEN', '')
GITHUB_FORK_URL = os.getenv('GITHUB_FORK_URL', '')
GITHUB_UPSTREAM_URL = "https://github.com/hashicorp/terraform-provider-awscc"

# Git Configuration
GIT_USER_NAME = os.getenv('GIT_USER_NAME', 'TANGO Pipeline')
GIT_USER_EMAIL = os.getenv('GIT_USER_EMAIL', 'tango@example.com')

# PR Configuration
PR_WORK_DIR = "pr_workspace"
```

**Note**: The `.env` file in the root directory already contains `GITHUB_TOKEN`. The agent will automatically load it using `python-dotenv`.

## Out of Scope

- Automated PR merging (requires maintainer approval)
- PR status monitoring (checking if PR was merged)
- Handling PR review comments
- Updating existing PRs with new changes
- Creating PRs for failed resources

## Success Metrics

- Successfully create PR for validated resource
- PR passes HashiCorp's CI checks
- DynamoDB accurately tracks PR status
- Zero resource leaks (temp directories cleaned up)
- Clear error messages for all failure modes
